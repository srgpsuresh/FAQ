MODULE 5 — Exception Handling

Handle runtime errors gracefully to maintain application stability, improve debugging, and provide meaningful responses to users.

  • Why Exception Handling? – Prevents application crashes and handles unexpected runtime errors.
  • Exception – Represents an error that occurs during program execution.
  • try – Wraps code that may throw an exception.
  • catch – Catches and handles exceptions thrown from the try block.
  • finally – Executes cleanup code whether an exception occurs or not.
  • throw – Throws a new exception while preserving the current execution flow.
  • throw ex – Re-throws an exception but resets the original stack trace (generally avoid).
  • throw; – Re-throws the current exception while preserving the original stack trace.
  • Custom Exception – Create business-specific exceptions such as OrderNotFoundException.
  • Exception Filters – Handle exceptions conditionally using when expressions.
  • Global Exception Handling – Centralizes exception handling for the entire application.
  • Exception Handling Middleware – Captures unhandled exceptions in the ASP.NET Core request pipeline.
  • ProblemDetails – Returns standardized RFC 7807 error responses from Web APIs.
  • Logging – Records exceptions using ILogger, Serilog, NLog, or Application Insights.
  • Business Exception – Represents domain validation errors like "Insufficient Stock".
  • Validation Exception – Indicates invalid user input or model validation failures.
  • HTTP Status Codes – Maps exceptions to responses such as 400, 401, 403, 404, 409, and 500.
  • Real-Time Usage – Order Service returns ProblemDetails and logs errors while preventing sensitive information leakage.
  • Best Practice – Handle exceptions globally, log them centrally, and return user-friendly error messages.

1. What is Saga Pattern?

Saga is a design pattern used to manage a business transaction across multiple microservices.

Each microservice performs its own local transaction. If something fails, we perform a compensating action.

Example

Order
  ↓
Payment
  ↓
Inventory
  ↓
Shipping

If Shipping Fails

Shipping Failed
      ↓
Release Inventory
      ↓
Refund Payment
      ↓
Cancel Order

2. Choreography

In Choreography, there is no central coordinator.

Each service performs its work and publishes an event. Another service listens to that event and performs its work.

Simple Flow

Order Service
     |
     | OrderCreated
     ↓
Payment Service
     |
     | PaymentCompleted
     ↓
Inventory Service
     |
     | InventoryReserved
     ↓
Shipping Service

Failure Flow

ShippingFailed
      ↓
Inventory Service
      ↓
Release Inventory
      ↓
Payment Service
      ↓
Refund Payment
      ↓
Order Service
      ↓
Cancel Order

Key Point

Choreography = No central controller.

Services communicate using events.

3. Orchestration

In Orchestration, a central Saga Orchestrator controls the workflow.

Simple Flow

              Saga Orchestrator
                      |
          ┌───────────┼───────────┐
          ↓           ↓           ↓
        Order       Payment    Inventory
                                  |
                                  ↓
                              Shipping

Normal Flow

Orchestrator
     ↓
Create Order
     ↓
Process Payment
     ↓
Reserve Inventory
     ↓
Create Shipment

Failure Flow

Shipping Failed
      ↓
Orchestrator
      ↓
Release Inventory
      ↓
Refund Payment
      ↓
Cancel Order

Orchestration = Central controller manages the workflow.

4. Choreography vs Orchestration

Feature Choreography Orchestration
Coordinator No Yes
Communication Events Commands / Events
Workflow Distributed Centralized
Simple workflow Good Good
Complex workflow Difficult Better
Debugging More difficult Easier

6. Interview Answer

How do you explain Saga Pattern?

Saga manages a transaction that spans multiple microservices. Each service performs a local transaction. If a step fails, compensating transactions are executed.

What is Choreography?

Choreography has no central coordinator. Services communicate through events.

What is Orchestration?

Orchestration uses a central Saga Orchestrator to control the workflow and compensation actions.

When would you use each?

Use Choreography for simple, event-driven workflows.

Use Orchestration for complex workflows where centralized control and visibility are important.

Orchestration = Orchestrator → Service → Service → Service

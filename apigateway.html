API Gateway - 20 Important Interview Points

1. What is an API Gateway?
Answer
API Gateway is the single entry point between clients and backend microservices.
Why?
It centralizes routing, security, throttling, authentication and monitoring.
Real-Time Scenario
Angular calls /api/orders; Gateway routes the request to Order Service.
2. Why do we need an API Gateway?
Answer
To avoid exposing every microservice directly to clients.
Why?
It provides centralized security and simplifies client communication.
Scenario
Client calls one Gateway instead of directly calling Order, Payment and Customer services.
3. How does API Gateway route requests?
Answer
Gateway matches the incoming URL and forwards it to the configured backend service.
Scenario
/orders/* → Order Service, /payments/* → Payment Service.
4. How does API Gateway handle authentication?
Answer
Gateway validates the JWT token before forwarding the request.
Why?
Invalid or missing tokens can be rejected at the edge before reaching services.
Scenario
Invalid JWT → 401 Unauthorized.
5. What is Authorization at Gateway?
Answer
Authorization determines whether the authenticated user can access a particular API.
Scenario
Admin can call /api/users/delete, while a normal user cannot.
6. What is Rate Limiting?
Answer
Rate limiting restricts the number of requests allowed from a client within a time period.
Why?
Prevents abuse and protects backend services.
Scenario
Allow 100 requests per minute per customer.
7. What is Throttling?
Answer
Throttling controls traffic when the system is overloaded.
Scenario
During a flash sale, Gateway limits excessive requests reaching Order Service.
8. How does Gateway improve security?
Answer
Gateway provides a controlled public entry point instead of exposing internal services.
Why?
Reduces the attack surface of the microservices.
Scenario
Payment Service remains private inside the network.
9. What is SSL/TLS termination?
Answer
Gateway terminates HTTPS connections and securely communicates with backend services.
Why?
Centralizes certificate management.
10. What is Request Transformation?
Answer
Gateway can modify headers, URLs or request data before forwarding the request.
Scenario
Add correlation ID and tenant ID to every request.
11. What is Response Transformation?
Answer
Gateway can modify or combine backend responses before returning them to the client.
Scenario
Hide internal service fields before returning customer data.
12. What is Aggregation in API Gateway?
Answer
Gateway combines responses from multiple services into a single client response.
Why?
Reduces multiple network calls from the client.
Scenario
Dashboard request → Customer + Orders + Payment services → one response.
13. How does Gateway handle service failure?
Answer
Gateway can use timeout, retry and circuit breaker policies.
Scenario
Payment Service is unavailable → Gateway stops repeatedly calling it after failures.
14. What is Load Balancing?
Answer
Gateway distributes requests across multiple healthy instances of a service.
Scenario
Order Service has 5 instances; Gateway distributes traffic among them.
15. What is API Versioning at Gateway?
Answer
Gateway routes different API versions to the appropriate backend implementation.
Scenario
/api/v1/orders → old service, /api/v2/orders → new service.
16. How does Gateway handle CORS?
Answer
Gateway can enforce which frontend applications are allowed to call APIs.
Scenario
Allow only the company's Angular application origin.
17. How does Gateway support Logging and Monitoring?
Answer
Gateway records request, response, latency, errors and correlation information.
Why?
Helps trace and troubleshoot distributed requests.
Scenario
Track one CorrelationId across Gateway → Order → Payment.
18. What is Caching at API Gateway?
Answer
Gateway temporarily stores frequently requested responses.
Why?
Reduces backend load and improves response time.
Scenario
Product catalog can be cached instead of querying Product Service every time.
19. What happens when Gateway itself fails?
Answer
Deploy multiple Gateway instances behind a load balancer for high availability.
Why?
Avoids a single point of failure.
Scenario
Gateway Instance 1 fails → traffic moves to Gateway Instance 2.
20. Explain the complete API Gateway flow.
Interview Answer
Client → Gateway → Authentication → Authorization → Rate Limit → Routing → Service → Response.
Real-Time Scenario
Angular → Azure APIM → JWT validation → Order API → Database → Response.
Why?
Gateway provides one controlled entry point for security, traffic management, routing and observability.

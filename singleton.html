1. What is Singleton?

Singleton Design Pattern ensures that only one instance of a class is created throughout the application and provides a common access point to that instance.

Interview Answer - 30 Seconds

Singleton is a creational design pattern. We use it when we need exactly one instance of a class throughout the application.

We make the constructor private, keep a static instance, and expose that instance through a static property or method.

In modern .NET applications, we generally prefer using Dependency Injection with AddSingleton().

2. Simple C# Singleton Code


public sealed class AppConfiguration
{
    private static readonly AppConfiguration _instance =
        new AppConfiguration();

    private AppConfiguration()
    {
    }

    public static AppConfiguration Instance
    {
        get { return _instance; }
    }

    public string ConnectionString { get; set; }
}

Usage


var config1 = AppConfiguration.Instance;
var config2 = AppConfiguration.Instance;

Console.WriteLine(config1 == config2);

Output


True

Both config1 and config2 point to the same object.

3. Why These Keywords?

Keyword Purpose
private constructor Prevents external code from creating an object using new.
static Makes the instance belong to the class.
sealed Prevents inheritance.
Instance Provides access to the single instance.
readonly Prevents replacing the instance after initialization.

5. Real-Time Example

Imagine an application configuration component that should have one shared instance.

Example Use Cases

  • Application configuration
  • Shared in-memory cache
  • Metrics collector
  • Stateless shared services
  • Application-wide coordination components

Important Interview Point

Singleton does not mean that every shared object should be global.

Shared mutable state can create concurrency and testing problems.

6. Singleton in ASP.NET Core

In modern ASP.NET Core applications, we normally don't need to manually implement the Singleton pattern.

Instead, use the built-in Dependency Injection container. 


builder.Services.AddSingleton<IAppConfiguration,
                             AppConfiguration>();

Inject the Service


public class EmployeeService
{
    private readonly IAppConfiguration _config;

    public EmployeeService(IAppConfiguration config)
    {
        _config = config;
    }
}

The DI container manages the lifetime of the service.

7. Dependency Injection Lifetimes

Lifetime Instance Behavior
AddTransient() New instance every time it is requested.
AddScoped() One instance per request/scope.
AddSingleton() One instance for the DI container lifetime.

8. Singleton Interview Questions

Q1. Why private constructor?

To prevent external code from creating objects using new.

Q2. Why static instance?

So that the instance belongs to the class rather than a particular object.

Q3. Why sealed?

To prevent inheritance and avoid subclasses creating additional instances.

Q4. Is Singleton thread-safe?

It depends on the implementation. The initialization approach must be thread-safe when multiple threads can access the Singleton concurrently.

Q5. Singleton vs Static Class?

A Singleton is an actual object/instance. It can implement interfaces and participate in Dependency Injection.

A static class cannot be instantiated and is generally less flexible for abstraction and testing.

Q6. What would you use in ASP.NET Core?

Prefer the built-in Dependency Injection container with AddSingleton<T>() instead of manually implementing Singleton in most application code.
